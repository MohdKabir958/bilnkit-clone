# Vendor directory

The directory now shows compact responsive cards with primary category, approval, manual availability, city/locality, product count and current-order count. Workspace search, city, approval, availability and primary-category filters go to an administrator-only bounded paginated endpoint with server totals. Cards do not fetch or contain bank details. The details drawer retrieves one store and exposes Overview, Products, Orders, Inventory, Location & Coverage, Working Hours, Compliance, Commission, Payouts and Audit. Sensitive panels mount only when their tab is selected; audit/products/orders have independent bounded pagination.

Open/close writes use the existing authorized endpoint and update only after acknowledgement. Closing requires confirmation explaining current orders. A refused write leaves the displayed state unchanged and shows the backend error. Opening is explicitly a manual setting, not a serviceability override. Existing profile, pin, commission, compliance and payout controls retain their endpoints and authorization. Daily hours remain owned by the Vendor app; exceptional administrative assistance remains reachable.

Verified: 3 focused UI tests, admin TypeScript passed. New real PostgreSQL tests cover pagination, totals, filters, safe field selection and role isolation; execution is blocked by local database permissions. Backend source type-check reports only stale generated RiderInvitation client errors (see Task 6); no passing backend build is claimed. Full admin regression updates and screenshots follow integration.
