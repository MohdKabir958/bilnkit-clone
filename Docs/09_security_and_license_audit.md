# Security and commercial license review

Root `LICENSE` is MIT, copyright 2026 Kraveo Technologies / Tribal-Chief-001. Retain its notice and disclaimer in redistributions. It grants code permissions, not trademark rights or blanket ownership of third-party assets.

`node scripts/license_inventory.mjs` inventories 1,083 lockfile package records (including dev/optional and platform variants) in `evidence/node-licenses.json`. This is metadata, not a legal clearance. MIT/ISC/BSD require notices; Apache packages require their license/notice terms; MPL-2.0 has file-level source obligations when applicable; OFL fonts require the font license and reserved-name rules; CC-BY assets require attribution. Unused GSAP/Lenis were removed from the landing page and its dependency lock. The lockfile omits license metadata for limiter/xmlhttprequest-ssl; their installed LICENSE files were inspected and contain MIT terms. Flutter bundles package notices; `packages/kraveo_ui/LICENSE` preserves MIT and the bundled Bricolage/Plus Jakarta font OFL notices. Audit the final distributed APK notices and font provenance before release.

Asset review remains open for inactive inherited marketing images/screenshots, downloaded food/portrait photos, shared fonts and proprietary service branding. The active apps and websites now use the Grozo wordmark prepared from the user's supplied reference; see `branding/README.md`. Obsolete standalone logos were removed. Historical design screenshots remain for audit, not legally cleared. Active landing pages do not advertise invented operating metrics, testimonials or availability. Original code copyright notices remain unchanged.

Dependency scan: backend production audit initially reported two critical and two high package findings (including propagated express/firebase-admin reports). Lockfile updates to proxy-addr 2.0.8 and busboy 3.2.3 address the listed advisories; follow-up production audit reported zero. Admin production audit reported zero. Automated audit does not establish absence of vulnerabilities; mobile/dev dependencies and independent review remain necessary.

Existing protections inspected: scrypt partner passwords, JWT expiry/version revocation/account checks, timing-safe admin passcode comparison, login throttling, role/resource checks, parameterized Prisma queries, raw-body payment HMACs, idempotency/transaction locks, room authorization, role-filtered order views and image signature/dimension validation. Test-only shortcuts are confined to test mode. New development payment disablement fails closed on signatures and cannot be enabled in production.

Phase 4 remediation: mobile bearer tokens use platform secure storage with legacy migration; Android backup is disabled; production startup enforces secret strength, owned HTTPS origins and persistent upload configuration. Release builds require owned signing keys and reject the debug Firebase bypass. JWT algorithms and socket token expiry are enforced; production sockets validate configured origins. Active delivery GPS requires an approved assigned rider, expires after five minutes and is deleted when no active delivery remains. Historical rider views remove exact addresses, phone numbers and free-text notes. Support cases/replies are authorized and persisted; account deletion deidentifies them. Offer acceptance and expiry use a consistent row lock order. Notification outbox writes batch/defer unconfigured providers. Production logs are structured JSON with credential/OTP/contact/address redaction.

Before launch: replace the shared admin passcode workflow with an operator-approved access/MFA policy; independently assess the application; validate real service accounts, device permissions and release artifacts; assign support/legal ownership. Process-local rate limits and maintenance scheduling target one API instance; distributed rate limiting/worker coordination require a separate scale review. No legal compliance is claimed. Indian consumer/e-commerce, food safety/FSSAI where applicable, privacy/data protection, GST/invoices, payments and rider obligations require qualified review.

Phase 2: address mutation/query is customer-owned; admin geography writes require ADMIN and commit audit records in the same transaction; versioned order routes reuse authentication/rate limits. New order views expose exact delivery coordinates/house only to the customer, assigned rider and admin, with coarse locality for stores and rider pool. Serviceability revalidates under row locks at checkout. Configurable maps validate responses, enforce response bounds and do not expose provider credentials. Adversarial verification found and fixed a late-capture race: payment confirmation now cancels expired checkout under the order lock and refunds captured money even when maintenance has not run.

Phase 3: vendor SKU, stock and stock-history APIs check store ownership and partner approval; admin inventory filters are role-restricted. Product edits re-enter moderation, stock writes use versions and idempotency, checkout snapshots are created under SKU locks, and the MRP guard protects legacy writers too. New stock/photo fields contain real configured values, not generated production listings. Mobile API/socket targets are supplied by build configuration; debug defaults to the emulator backend and releases reject non-HTTPS targets. Release debug signing was removed in Phase 4; real signing and device validation remain operator tasks.
