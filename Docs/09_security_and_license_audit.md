# Security and commercial license review

Root `LICENSE` is MIT, copyright 2026 Kraveo Technologies / Tribal-Chief-001. Retain its notice and disclaimer in redistributions. It grants code permissions, not trademark rights or blanket ownership of third-party assets.

`node scripts/license_inventory.mjs` inventories 1,085 lockfile package records (including dev/optional and platform variants) in `evidence/node-licenses.json`. This is metadata, not a legal clearance. MIT/ISC/BSD require notices; Apache packages require their license/notice terms; MPL-2.0 has file-level source obligations when applicable; OFL fonts require the font license and reserved-name rules; CC-BY assets require attribution. GSAP has a custom standard license and must be reviewed against its installed license text/current terms. The lockfile omits license metadata for limiter/xmlhttprequest-ssl; their installed LICENSE files were inspected and contain MIT terms. Flutter transitive notices still need a distributable license bundle before release.

Asset review remains open: inherited root logos, marketing images/screenshots, downloaded food/portrait photos, shared fonts and proprietary service branding need provenance and redistribution review. The neutral admin/shared mark and new Android geometric icon avoid relying on inherited logo artwork on those surfaces; inherited files and marketing pages remain preserved for audit, not legally cleared.

Dependency scan: backend production audit initially reported two critical and two high package findings (including propagated express/firebase-admin reports). Lockfile updates to proxy-addr 2.0.8 and busboy 3.2.3 address the listed advisories; follow-up production audit reported zero. Admin production audit reported zero. Automated audit does not establish absence of vulnerabilities; mobile/dev dependencies and independent review remain necessary.

Existing protections inspected: scrypt partner passwords, JWT expiry/version revocation/account checks, timing-safe admin passcode comparison, login throttling, role/resource checks, parameterized Prisma queries, raw-body payment HMACs, idempotency/transaction locks, room authorization, role-filtered order views and image signature/dimension validation. Test-only shortcuts are confined to test mode. New development payment disablement fails closed on signatures and cannot be enabled in production.

Open findings requiring remediation before launch: shared admin passcode/MFA policy; JWT storage in SharedPreferences across mobile clients; raw rider fixes can still be stored off-duty/without active delivery; campus geography; local upload durability; unproven backup/restore; inherited debug release signing; external FCM/OAuth client identities; unfinished complaint/support lifecycle. No legal compliance is claimed. Indian consumer protection/e-commerce, food safety/FSSAI as applicable, privacy/data protection, GST/invoices, payments and rider obligations require qualified review.

Phase 2: address mutation/query is customer-owned; admin geography writes require ADMIN and commit audit records in the same transaction; versioned order routes reuse authentication/rate limits. New order views expose exact delivery coordinates/house only to the customer, assigned rider and admin, with coarse locality for stores and rider pool. Serviceability revalidates under row locks at checkout. Configurable maps validate responses, enforce response bounds and do not expose provider credentials. Adversarial verification found and fixed a late-capture race: payment confirmation now cancels expired checkout under the order lock and refunds captured money even when maintenance has not run.

Phase 3: vendor SKU, stock and stock-history APIs check store ownership and partner approval; admin inventory filters are role-restricted. Product edits re-enter moderation, stock writes use versions and idempotency, checkout snapshots are created under SKU locks, and the MRP guard protects legacy writers too. New stock/photo fields contain real configured values, not generated production listings. Mobile API/socket targets are supplied by build configuration; debug defaults to the emulator backend and releases reject non-HTTPS targets. Original release debug signing and other Phase 4 security items remain open.
