# Flutter welcome pages

Branch: `feature/flutter-start-pages` (based on the completed marketplace branch).

The shared native Clerk entry now has three role-specific welcome pages. Customers see nearby-shop discovery, baskets and doorstep delivery. Vendors see stock, packing and rider handover. Riders see duty, nearby offers and delivery verification. The existing Grozo theme, green actions, fonts, rounded surfaces and dark rider palette are retained.

Get started, sign-in/recovery and account creation still open the official native Clerk SDK. There are no password fields, replacement tokens or authentication shortcuts in Flutter. A signed-in Continue action rechecks business authorization with the backend. Partner approval, application and sign-out actions remain available. Error messages are announced to accessibility services. The page scrolls on short screens and supports large text.

All three apps are version 1.12.0+19. Connected development-signed ARM64 builds target `https://grozo-backend-3wdf.onrender.com`; they preserve Android package IDs. Firebase is disabled only in these staging builds because owned Android Firebase client configuration is unavailable. Native provider login, real-device installation, push delivery and outdoor GPS still require owner/device checks.

Actual production-widget screenshots: `../ui-ux/start-pages/{customer,vendor,delivery}/login.png`. They use rendering-only native SDK fixtures and are not physical-device or hosted-Clerk captures. Other screenshots in that directory are regenerated unchanged workflows. No screenshots were generated by an image model.

Verification logs and machine-readable Flutter test results are in `evidence/`. Four new welcome tests check all three roles at 320px / 160% text and verify recovery delegates to native Clerk while signed-in Continue rechecks Grozo. Shared session tests retain token refresh, logout and account-switch coverage.
