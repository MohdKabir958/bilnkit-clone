# Implemented changes

The existing applications, Prisma UUIDs, historical grouped orders and financial ledger remain. The current customer home/reference theme was not redesigned.

- **Authentication/deployment:** `deploymentContract`, `clientContract`, configuration diagnostics and client headers identify wrong protocol/auth/Clerk instance without erasing sessions. Production cutover remains explicit. Admin CSP permits exact trusted authentication resources and required workers; no wildcard replacement.
- **Payments/checkout:** `paymentCapabilities`, `checkoutRecovery` and durable `PaymentCreation` enforce real availability and attempt ownership. Network calls happen outside locked transactions. Unknown provider outcomes are observed rather than blindly retried. The customer cannot pay from a local estimate.
- **Packing/capacity/dispatch:** `capacity`, `preparation`, `routing` and `operationalSla` connect store load, fresh eligible riders, estimates, dispatch timing, busy mode and recovery deadlines. GPS validates accuracy/time/replay/movement and enforces independent reviewed exceptions at pickup/drop-off.
- **Inventory:** `inventory` and product routes add optional FEFO lots/expiry, physical packing and unusable-stock disposition, inspection of cancelled packed orders, stock corrections and batch-aware availability. Removed shortage packs are recorded missing in the proposal transaction.
- **Item changes/refunds:** `orderAdjustments` adds customer-owned versioned decisions and complete server-calculated baskets. Same/cheaper replacements, removals and quantity reductions adjust snapshots/reservations and COD due or a partial online refund. Higher charges are explicitly refused with supported alternatives. `partialRefunds` distinguishes not-yet-submitted, unknown, pending and confirmed processing; original captured amounts remain immutable.
- **Cash/support/operations:** `cashReconciliation`, `supportCases`, `supportEvidence` and `operationsReadiness` add append-only receipt/dispute/close evidence, case categories/priorities/ownership/deadlines, private photo integrity/retention and audited exception resolution.
- **Durable jobs/notifications:** `jobs`/`backgroundWorker` provide fenced leases, heartbeat, independent lanes, bounded attempts and retry diagnostics. Notification outbox/retries suppress expired offers and preserve account ownership. Public support replies now stage an atomic intent, retain hashed per-device acknowledgments under a lease fence, retry transient failures and use generic non-sensitive lock-screen text. All three apps validate the new case/note payload and open the authorized private thread. Socket/poll recovery remains available when push is unconfigured.
- **Seller/finance:** `sellerCompliance`, `orderReceipt`, `payoutReadiness` and `disbursementAdapter` add controlled compliance verification, honest informational receipts and payout eligibility/holds. Sandbox dry runs do not transfer money; no live bank adapter is enabled.
- **Flutter:** customer payment/recovery/item-approval/private support; vendor physical stock/alternatives/packing/IST hours/owned performance and low-stock alerts; delivery location refresh/expiry and stage details. Checkout displays bounded server delivery windows as estimates, and suppresses that window when fulfillment is unavailable. All use existing themes and authorization flows. Release versions match at 1.16.0+24; the customer About version now matches the package version.
- **Admin:** integrated SLA, exceptions, physical inventory, COD reconciliation, seller compliance and payout-readiness panels extend the current portal. The Operations page now includes a lazy-loaded job-history/safe-retry and seller-expiry panel, and exception follow-up can retain or change its approved administrator owner.
- **Infrastructure/QA:** persistent private/public storage layout, safe database/file recovery tools, schema-aware readiness, redacted diagnostics, compatible dependency security patches, complete backend regression, constrained-pool pricing repetitions and measured mixed pilot.

See `OPERATIONS_GUIDE.md` for navigation and `04_DATABASE_MIGRATIONS.md` for persistence. Exact verification belongs in `06_FULL_TEST_RESULTS.md`; mocked provider tests are not described as live integration.

Test-contract updates are deliberate: current-server checkout fixtures now supply explicit payment methods; a missing/rejected quote cannot authorize payment. Coupon/order/idempotency assertions remain, and legacy quote-controller compatibility tests still exercise 404 responses. Support fixtures use the implemented categorized request title. New stock, GPS, refund-recovery and store-ownership assertions verify actual behavior; no failed test was skipped to force success.
